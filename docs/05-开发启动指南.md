# 05 · 开发启动指南

## 1. 启动原则：先奠基，再并行

4 人**不能**一上来就各写各的。共享基础（环境、工程骨架、数据库、接口契约）必须先统一，否则联调时会大量返工。启动分两个阶段：

- **第 1 阶段（奠基，约 1 天，协作/结对）**：环境统一、仓库就绪、数据库建表、前后端最小骨架、接口契约。
- **第 2 阶段（功能开发，长期，高度并行）**：按模块 + 接口契约分头开发。

## 2. 第一步：环境与仓库（第 1 天上午）

| 成员     | 需要安装/准备                               |
| -------- | ------------------------------------------- |
| 全栈     | MySQL 8.0、Redis、数据库建表脚本、seed 数据 |
| 后端 A/B | Python 3.11+、Git、PyCharm                  |
| 前端     | Node.js 18+、npm、VS Code                   |

仓库操作（全员）：

```bash
git clone https://github.com/suwa-ko/FinLend.git
cd FinLend
git checkout -b dev
```

## 3. 第一步：最小可运行骨架（第 1 天下午）

### 后端（A 牵头、B 参与）

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows（macOS/Linux 用 source .venv/bin/activate）
pip install fastapi uvicorn sqlalchemy pymysql pydantic pyjwt "passlib[bcrypt]" redis python-multipart
```

骨架内容：`main.py`（含 `/health` 接口）、统一返回 `{code, message, data}`、全局异常处理、数据库连接、JWT 依赖注入。

### 前端（前端成员）

```bash
npm create vite@latest frontend -- --template vue
cd frontend && npm install
npm install element-plus pinia vue-router axios
```

骨架内容：Vue Router 路由、Pinia 状态、Axios 拦截器（统一携带 JWT、统一错误处理）、一个占位页面。

### 数据库（全栈）

执行 `docs/03-数据库设计.md` 的建表脚本，并插入 seed 数据（管理员账号、测试用户、2~3 个贷款产品）。

## 4. 第一步：接口契约（全员共识，并行开发的前提）

统一返回结构：

```json
{ "code": 0, "message": "ok", "data": {} }
```

约定：`code = 0` 表示成功，非 0 为错误码。

示例（登录接口）：

```
POST /api/v1/auth/login
请求：{ "username": "admin", "password": "123456" }
响应：{ "code": 0, "message": "ok", "data": { "access_token": "xxx", "token_type": "bearer" } }
```

先定「认证 + 产品」两个模块的契约，其余模块在开发前补充。

## 5. 能否同时工作？——能，但守住契约

第 2 阶段各成员并行：

| 成员   | 并行任务（对应 M1/M2）       | 依赖                     |
| ------ | ---------------------------- | ------------------------ |
| 前端   | 登录/注册页、产品列表/详情页 | 只需契约，可先 mock 数据 |
| 后端 A | 认证/用户模块、贷款产品模块  | 数据库表（全栈先建好）   |
| 后端 B | 借款申请模块                 | 数据库表 + 产品接口      |
| 全栈   | 建库/seed、联调、进度协调    | 工程骨架                 |

并行三要素：

1. **契约先行**：前端对着契约 mock，不必等后端。
2. **骨架共享**：后端两人先合搭骨架，再分模块开发。
3. **数据库先行**：全栈第 1 天就建表，后端写接口才有地基。

## 6. Git 协作流程

- `main`：稳定分支（每个里程碑合入）。
- `dev`：集成分支（日常合并）。
- `feature/xxx`：个人功能分支（如 `feature/auth`、`feature/product`）。
- 每天结束把 feature 合并回 `dev`，避免长期分叉冲突。

## 7. M1 检查点（全部完成即可进入 M2）

- [ ] 后端能跑 `/health`，统一返回/异常/JWT 生效
- [ ] 数据库表已建，seed 数据可登录
- [ ] 前端能启动，Axios 封装生效
- [ ] 注册/登录接口跑通（前端 → 后端 → 数据库全链路）
- [ ] 接口契约文档已落地
