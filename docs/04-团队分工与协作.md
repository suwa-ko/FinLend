# 04 · 团队分工与协作

> 项目类型：「综合设计 1」课程设计项目
> 报告日期：2026年9月21日
> 撰写人：宋沛铮
> 版本：v1.0
> 工具使用：DeepSeek Harness、Codex

## 1. 分工原则

1. **每人都有可展示的代码贡献**。
2. **工作量均衡**，避免出现「前期/后期没活干」的空档。
3. **数据库设计由后端主导**：后端写 ORM 模型最清楚业务字段，不孤立外包给某个人。
4. **接口先行**：前后端先约定 API 契约，再各自并行开发。

## 2. 原方案评估（前端 + 后端 + 数据库 + 联调）

| 优点                 | 隐患                                                         |
| -------------------- | ------------------------------------------------------------ |
| 按技术分层，思路直观 | 数据库不是 1/4 工作量：表设计集中在前 1~2 周                 |
| 角色边界清晰         | 联调是「阶段」不是「全职角色」：代码没出来前无事可做         |
| —                    | 只做联调的人对代码不熟，排查问题慢，答辩难以说明代码贡献     |
| —                    | 后端业务（利息/审批/放款/还款/逾期）是项目大头，1 人压力过大 |

**结论**：能跑，但不够均衡。建议调整为「按业务模块分后端 + 一名全栈胶水角色」。

## 3. 推荐分工

| 角色         | 人数 | 职责                                                    | 主要产出物                         |
| ------------ | ---- | ------------------------------------------------------- | ---------------------------------- |
| 前端开发     | 1    | Vue 用户端 + 管理端全部页面、路由、状态管理、Axios 封装 | 页面、组件、路由、接口封装         |
| 后端开发 A   | 1    | 用户/认证、贷款产品、预留信用评估接口(stub)             | 对应 API + Service                 |
| 后端开发 B   | 1    | 借款申请、审批、放款、还款、逾期、账户                  | 对应 API + Service                 |
| 全栈（胶水） | 1    | 数据库落地、前后端联调、测试、部署、文档、进度协调      | 建表脚本、测试用例、部署方案、文档 |

## 4. 数据库设计归属

| 任务                                           | 负责人                   |
| ---------------------------------------------- | ------------------------ |
| 表结构设计（字段、关系、索引）                 | 后端 A/B 主导 + 全栈协同 |
| 建表 SQL 脚本                                  | 全栈                     |
| 初始化数据（seed：产品、管理员账号、测试用户） | 全栈                     |
| 索引/慢查询优化                                | 全栈 + 后端 A/B          |

## 5. 分阶段职责矩阵（对应 README 里程碑 M1~M4）

| 阶段              | 前端                    | 后端 A                     | 后端 B             | 全栈                     |
| ----------------- | ----------------------- | -------------------------- | ------------------ | ------------------------ |
| M1 脚手架+登录    | 项目初始化、登录/注册页 | 认证/用户模块              | 熟悉工程、接口契约 | 建库建表、seed、环境搭建 |
| M2 产品+申请+审批 | 产品列表/详情、申请表单 | 产品、预留信用评估接口     | 申请、审批 API     | 联调产品/申请链路        |
| M3 放款+还款+逾期 | 还款页面、还款计划展示  | 预留额度字段收尾、协助联调 | 放款、还款、逾期   | 定时任务、联调、测试     |
| M4 后台+通知+演示 | 管理端看板、消息页      | 报表接口、收尾             | 逾期催收、收尾     | 部署、演示材料、文档整合 |

## 6. 协作约定

1. **Git 分支**：`main`（稳定）→ `dev`（集成分支）→ `feature/xxx`（个人功能分支）；前端、后端、数据库脚本分目录管理。
2. **接口契约先行**：每个模块先定好请求/响应结构（用 FastAPI `/docs` 或接口文档落地），前后端按契约并行，不互相等。
3. **统一返回结构**：后端统一 `{ code, message, data }`，错误码提前约定，前端按 code 处理。
4. **联调节奏**：M2 起每 2 天一次前后端联调；全栈负责记录问题清单并跟进闭环。
5. **进度同步**：建议每日简短同步（已完成/进行中/阻塞），由全栈汇总到项目 README 或进度表。

## 7. 答辩贡献展示建议

- **前端**：演示用户端 + 管理端页面，讲路由权限、表单校验、接口封装。
- **后端 A**：讲认证、产品，以及信用评估预留接口的设计。
- **后端 B**：讲申请审批流、放款、还款计划生成、逾期罚息计算（重点展示利息公式的正确性）。
- **全栈**：讲数据库 ER 设计与建表、联调流程、测试用例、部署与文档，说明自己贯穿全流程的「胶水」价值。
