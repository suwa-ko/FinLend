# 04 · 团队分工与开发规范

> 项目类型：「综合设计 1」课程设计项目
> 初稿日期：2026年9月21日 · 撰写人：宋沛铮
> 修订日期：2026年9月22日 · 版本：v1.1（计划）
> 工具使用：DeepSeek Harness、Codex

## 1. 分工原则

每个交付项指定一名主责和一名评审者。Web 与安卓分别有实施负责人，避免单名前端同时承担三套界面的全部工作。后端按业务模块划分，数据库随对应业务共同设计；联调和质量由全员承担，全栈协调记录。

本仓库目前只有文档。下列目录、接口和命令用于后续实现项目，不表示已经存在可运行代码。

## 2. 角色与产出

| 角色 | 主责 | 评审/协作 | 可交付证据 |
| --- | --- | --- | --- |
| 前端（1 人） | Web 用户端/管理端、表单与路由、Axios 封装 | 评审安卓 UI 和用户流程 | 页面、接口映射、双端操作脚本 |
| 后端 A（1 人） | 用户认证、会话/上传、产品、消息与默认风控接口 | 评审 B 的权限、状态和数据约束 | API、模型/迁移、认证和上传验证 |
| 后端 B（1 人） | 申请/审批/签约、放款、还款、逾期、账户 | 评审 A 的鉴权与接口设计 | 业务服务、迁移、计算与事务测试 |
| 全栈（1 人） | uni-app 安卓端、APK 打包、部署与联调协调 | 前端协助页面；A/B 负责各自迁移和测试 | 安卓页面、APK、设备记录、联调清单 |

数据库模型和迁移由 A/B 为各自模块负责，全栈负责空库初始化与 seed 联调；复杂计算由 B 主责、A 复核。此分工是计划基线，M1 按成员实际技能调整人员对应关系，不减少安卓交付范围。

## 3. 分阶段职责矩阵

| 阶段 | 前端 | 后端 A | 后端 B | 全栈 |
| --- | --- | --- | --- | --- |
| M1（第 1–2 周） | Web 骨架、登录、表单规范 | 会话/用户/上传契约与基础实现 | 账务模型、金额算法、状态契约 | 安卓骨架、首次真机安装、登录、环境记录 |
| M2（第 3–5 周） | 产品、申请、审批与签约页 | 产品、模拟实名/上传、默认风控 | 申请审批、签约超时、幂等机制 | 安卓产品、认证、申请/撤销/签约 |
| M3（第 6–9 周） | 账户、还款、站内消息 | 消息/提醒、鉴权回归、协助事务测试 | 放款、还款、提前结清、逾期补算 | 安卓还款/消息、弱网与双端联调 |
| M4（第 10–12 周） | 页面收尾、可选报表 | 权限/上传/会话验收 | 并发与对账验收 | 签名 APK、安装手册、部署/恢复与演示整合 |

工作可并行推进，但未通过检查点的交付不能标记完成。M2 起每两天联调一次；每日文字同步完成项、下一步和阻塞，阻塞超过一个工作日安排结对排查。

## 4. 协作与变更规范

- 分支：main 保存里程碑版本，dev 集成，feature/* 完成小步任务。提交前同步 dev；通过评审和相关检查后合入，不要求每天强行合入未完成代码。
- 每个 PR 说明问题、最终行为、接口/数据库变更及验证结果。涉及金额和权限至少由另一名后端评审；客户端依赖的接口调整通知两端负责人。
- 需求变更先改 [02](02-功能需求分析.md)，同步 [03](03-数据库设计.md) 与接口契约，再实现。版本化迁移不能通过手工改演示库替代。
- .env、私钥、APK 签名密钥、真实身份资料不提交；提交 .env.example、虚构 seed、依赖锁定文件及可重复构建说明。
- 每个里程碑保存需求条目 → 接口/页面 → 测试或演示证据的对应关系。问题记录包含负责人、复现步骤、影响、状态。

## 5. 开工准备

### 5.1 环境与工程

实现项目建议目录为 backend/、frontend/、mobile/、docs/。M1 记录 Python、Node、MySQL、Redis、HBuilderX 和 Android 机型/版本；前端工具版本以 uni-app 模板与 Vite 的共同兼容范围为准。Windows 上 Redis 可使用 WSL2 或容器，记录端口和连接方式。

下面是**实现仓库中**的 PowerShell 初始化示例。应先创建 backend/、frontend/，正式协作安装锁定版本而非每人独立安装最新版：

```powershell
# 在 backend/ 下
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install fastapi uvicorn sqlalchemy pymysql pydantic pyjwt "passlib[bcrypt]" redis python-multipart apscheduler alembic pytest
# 保存验证通过的依赖版本；后续统一按 requirements/锁文件安装
```

Web 使用 Vue 3 + Vite 模板，安装 Element Plus、Pinia、Vue Router、Axios；安卓使用 uni-app Vue 3 模板和 uni-ui，不直接复制 Web 的 Element Plus 组件。

### 5.2 M1 必须验证的环境能力

- 后端 /health、数据库和 Redis 可连接；仅配置依赖不能视为鉴权已完成。
- 从空库执行**完整迁移**和 seed；[03 §6](03-数据库设计.md#6-建库与迁移示例) 只是示例，不能直接替代迁移。
- Web 与真机调用同一测试服务；手机使用服务端局域网 IP/域名，不能使用手机自身的 localhost。
- 先打一个可安装的测试 APK，验证网络访问、签名工具链、图片选择及安全存储可用；M4 再生成交付包。
- 为演示账户配置虚构身份与测试图片、授信和有初始化流水的模拟余额；业务数据重置后可重复演示。

## 6. 接口契约

### 6.1 格式与错误

前缀 /api/v1。请求体按业务定义，**响应**统一为：

```json
{
  "code": 0,
  "message": "ok",
  "data": { "amount": "12000.00", "annual_rate": "12.0000" }
}
```

ID、金额和利率用字符串；日期 YYYY-MM-DD、时间 ISO 8601 并带 +08:00。分页 data 包含 items、total、limit、offset，默认 limit=20，最大 100；排序显式指定稳定的第二排序键 id。

HTTP 状态与业务 code 同时使用：200/201 成功，401 未认证，403 权限不足/冻结，404 资源不存在，409 状态或幂等/报价冲突，422 参数错误，413 文件过大，415 格式不支持，429 限流，503 依赖不可用。失败 code 非零，message 不暴露堆栈；通过 X-Request-ID 关联日志。具体业务码写入 OpenAPI 示例。

### 6.2 会话契约

```text
POST /api/v1/auth/login
请求：{ "username": "demo_user", "password": "<演示密码>", "client_type": "ANDROID", "device_id": "<随机安装标识>" }
响应 data：{ "access_token": "<JWT>", "refresh_token": "<高熵随机串>", "token_type": "bearer", "expires_in": 7200 }

POST /api/v1/auth/refresh
请求：{ "refresh_token": "<当前刷新令牌>" }
响应 data：新的 access_token、refresh_token、token_type、expires_in

POST /api/v1/auth/logout
请求头：Authorization: Bearer <access_token>
效果：吊销当前 sid 对应会话；其他设备会话保持有效
```

管理员使用独立 /api/v1/admin/auth/login，公开用户登录不能签发 ADMIN 权限；刷新和退出共用会话服务。JWT 包含带主体类型的 sub（如 user:123/admin:123）、sid、jti、exp，固定算法校验。会话 7 天固定到期，刷新令牌轮换，账号冻结/退出时吊销，业务请求每次检查会话和账号状态。

客户端同一时刻只发一次刷新请求；收到 401 后刷新成功可重试一次，写操作必须沿用原 Idempotency-Key。刷新失败清除会话并跳转登录，不无限重试。

### 6.3 幂等与超时

提交申请、审批、签约、放款、还款等状态写接口携带 Idempotency-Key。服务端先校验身份与归属，再识别已完成请求；相同主体/操作/键/请求内容返回同一结果，内容不同返回 409。成功结果与业务同事务落库，见 [03 §3.15](03-数据库设计.md#315-幂等记录表-t_business_request本期建设)。

结果未知时查询申请/还款结果，或用原键和相同内容重试；客户端不能换新键自动再扣一次款。前端禁用重复点击只是交互措施，不能替代服务端幂等与事务。

### 6.4 契约版本与 Mock

设计期先提供请求/响应示例和错误码；实现后以 OpenAPI 导出文件做版本化契约，/docs 展示运行时契约。客户端可基于示例 Mock；合入时核对两者一致。破坏性变更须评估双端影响，不能声称任何业务升级都只需新增字段。

## 7. 验证责任与完成定义

“完成”须满足：需求及异常路径有实现、接口/迁移与文档一致、相关检查通过、评审意见处理完、可在集成环境演示。当前仓库未包含这些实现。

| 验证层次 | 主责 | 必需场景 |
| --- | --- | --- |
| 计算单元测试 | B，A 复核 | 三种方式、零利率、最后一期平账、月末、罚息补算、提前结清及费用 |
| 数据库集成测试 | A/B | 回滚、唯一约束、并发额度、重复还款、账实相符；使用 MySQL，不能用 SQLite 代替锁验证 |
| 会话与权限 | A | 轮换/吊销、冻结、用户/管理员隔离、附件越权、上传格式 |
| 双端验收 | 前端/全栈 | 同一账号跨端状态一致、签约撤销、弱网、401 续期、重复点击、真实 APK 安装 |
| 部署与恢复 | 全栈，各模块协作 | 锁定依赖安装、空库迁移、seed、备份恢复、任务单实例 |

## 8. 里程碑检查点

### M1 奠基

- [ ] 环境版本与测试设备已记录，Web/后端/安卓工程可启动
- [ ] 基础迁移、seed、/health 通过；JWT 与角色校验生效
- [ ] 双端注册登录、刷新和退出可演示；真机首次 APK 安装通过
- [ ] 上传/业务接口契约已定义；关键计算基准已建立

### M2 申请链路

- [ ] 双端模拟实名（含测试图片）、浏览、试算、提交/撤销/签约通过
- [ ] Web 审批、拒绝原因、签约超时与并发状态校验通过
- [ ] 黑名单/冻结/未实名/额度不足被拒绝，模拟风控不能绕过检查
- [ ] 幂等键与原子记录可验证，产品修改不改变申请快照

### M3 资金与消息

- [ ] 放款入账、三种计划、按期/逾期还款、提前结清全部跑通
- [ ] 重复/并发请求只产生一次记账，事务失败无部分更新
- [ ] 罚息重跑/漏跑、月末/零利率/舍入场景通过
- [ ] 订单、分摊、流水与余额对账通过，消息去重与前台轮询通过

### M4 交付

- [ ] 交付签名 APK、构建配置、安装说明和设备验证记录
- [ ] Web/安卓各完成“申请 → Web 审批放款 → 还款 → 结清”，金额和状态一致
- [ ] 核心阻塞缺陷为零；性能记录、权限验证、备份恢复证据完整
- [ ] 使用手册、部署说明、接口契约、演示数据和答辩材料齐备

## 9. 答辩贡献展示

前端展示 Web 流程与错误反馈；A 展示跨设备鉴权、附件归属与产品快照；B 展示计算规则、事务和重复请求处理；全栈展示 APK 真机操作、跨端一致性与可重复部署。每人用自己的实现及验证证据说明贡献，不将文档规划标成已经实现。
