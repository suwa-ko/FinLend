# 04 · 团队分工与开发规范

> 项目类型：「综合设计 1」课程设计项目
> 报告日期：2026年9月21日
> 撰写人：宋沛铮
> 版本：v1.0
> 工具使用：DeepSeek Harness、Codex

---

## 1. 分工原则

1. **每人都有可展示的代码贡献**。
2. **工作量均衡**，避免出现「前期/后期没活干」的空档。
3. **数据库设计由后端主导**：写 ORM 模型的人最清楚业务字段，不孤立外包给某个人。
4. **接口先行**：前后端先约定 API 契约，再各自并行开发。

## 2. 分工方案

**原方案评估**：按「前端 + 后端 + 数据库 + 联调」各 1 人分层，思路直观、角色边界清晰，但存在隐患——数据库工作量集中在前 1~2 周，之后基本闲置；联调是「阶段」而非「全职角色」，代码没出来前无事可做；且后端业务（利息 / 审批 / 放款 / 还款 / 逾期）是项目大头，1 人压力过大。

**故调整为**：按业务模块分后端 + 一名全栈胶水角色。

| 角色         | 人数 | 职责                                                    | 主要产出物                         |
| ------------ | ---- | ------------------------------------------------------- | ---------------------------------- |
| 前端开发     | 1    | Vue 用户端 + 管理端全部页面、路由、状态管理、Axios 封装 | 页面、组件、路由、接口封装         |
| 后端开发 A   | 1    | 用户/认证、贷款产品、预留风控与信用评估接口             | 对应 API + Service                 |
| 后端开发 B   | 1    | 借款申请、审批、放款、还款、逾期、账户                  | 对应 API + Service                 |
| 全栈（胶水） | 1    | 数据库落地、前后端联调、测试、部署、文档、进度协调      | 建表脚本、测试用例、部署方案、文档 |

**数据库设计归属**：表结构（字段、关系、索引）由**后端 A/B 主导 + 全栈协同**；建表 SQL 脚本、初始化 seed 数据（产品、管理员账号、测试用户）、索引与慢查询优化由全栈负责。关键点是表结构必须由写业务代码的人一起定，否则字段对不上 ORM 模型会返工。

## 3. 分阶段职责矩阵（对应 README 里程碑 M1~M4）

| 阶段              | 前端                    | 后端 A                     | 后端 B             | 全栈                     |
| ----------------- | ----------------------- | -------------------------- | ------------------ | ------------------------ |
| M1 脚手架+登录    | 项目初始化、登录/注册页 | 认证/用户模块              | 熟悉工程、接口契约 | 建库建表、seed、环境搭建 |
| M2 产品+申请+审批 | 产品列表/详情、申请表单 | 产品、预留风控/信用接口    | 申请、审批 API     | 联调产品/申请链路        |
| M3 放款+还款+逾期 | 还款页面、还款计划展示  | 预留额度字段收尾、协助联调 | 放款、还款、逾期   | 定时任务、联调、测试     |
| M4 后台+通知+演示 | 管理端看板、消息页      | 报表接口、收尾             | 逾期催收、收尾     | 部署、演示材料、文档整合 |

## 4. 协作规范

**分支策略**：`main`（稳定，每个里程碑合入）→ `dev`（集成分支，日常合并）→ `feature/xxx`（个人功能分支，如 `feature/auth`）。每天结束把 feature 合回 `dev`，避免长期分叉冲突；前端、后端、数据库脚本分目录管理。

**接口与返回结构**：每个模块先定好请求 / 响应结构（用 FastAPI `/docs` 落地），前端按契约 mock、不等后端。后端统一返回 `{ code, message, data }`，错误码提前约定，前端按 code 处理。

**节奏**：M2 起每 2 天一次前后端联调，全栈记录问题清单并跟进闭环；每日简短同步（已完成 / 进行中 / 阻塞）。

## 5. 开工准备（奠基阶段）

4 人**不能**一上来就各写各的。共享基础（环境、工程骨架、数据库、接口契约）必须先统一，否则联调时会大量返工。奠基阶段约 1 天协作 / 结对完成，之后进入长期并行。

| 成员     | 环境准备                              |
| -------- | ------------------------------------- |
| 全栈     | MySQL 8.0、Redis、建表脚本、seed 数据 |
| 后端 A/B | Python 3.11+、Git、PyCharm            |
| 前端     | Node.js 18+、npm、VS Code             |

仓库操作（全员）：

```bash
git clone https://github.com/suwa-ko/FinLend.git
cd FinLend
git checkout -b dev
```

**后端骨架**（A 牵头、B 参与）：

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows（macOS/Linux 用 source .venv/bin/activate）
pip install fastapi uvicorn sqlalchemy pymysql pydantic pyjwt "passlib[bcrypt]" redis python-multipart
```

骨架内容：`main.py`（含 `/health` 接口）、统一返回与全局异常处理、数据库连接、JWT 依赖注入。

**前端骨架**：

```bash
npm create vite@latest frontend -- --template vue
cd frontend && npm install
npm install element-plus pinia vue-router axios
```

骨架内容：Vue Router 路由、Pinia 状态、Axios 拦截器（统一携带 JWT、统一错误处理）、一个占位页面。

**数据库**：执行《03-数据库设计》的建表脚本，并插入 seed 数据（管理员账号、测试用户、2~3 个贷款产品）。

## 6. 接口契约（并行开发的前提）

统一返回结构：

```json
{ "code": 0, "message": "ok", "data": {} }
```

约定：`code = 0` 表示成功，非 0 为错误码。示例（登录接口）：

```
POST /api/v1/auth/login
请求：{ "username": "admin", "password": "123456" }
响应：{ "code": 0, "message": "ok", "data": { "access_token": "xxx", "token_type": "bearer" } }
```

## 7. 并行开发

奠基完成后即可高度并行，前提是守住契约：

| 成员   | 并行任务（对应 M1/M2）       | 依赖                     |
| ------ | ---------------------------- | ------------------------ |
| 前端   | 登录/注册页、产品列表/详情页 | 只需契约，可先 mock 数据 |
| 后端 A | 认证/用户模块、贷款产品模块  | 数据库表（全栈先建好）   |
| 后端 B | 借款申请模块                 | 数据库表 + 产品接口      |
| 全栈   | 建库/seed、联调、进度协调    | 工程骨架                 |

并行三要素：**契约先行**（前端对着契约 mock，不必等后端）、**骨架共享**（后端两人先合搭骨架再分模块）、**数据库先行**（全栈第 1 天就建表，后端写接口才有地基）。

## 8. 里程碑检查点

**M1（全部完成即可进入 M2）**：

- [ ] 后端能跑 `/health`，统一返回 / 异常 / JWT 生效
- [ ] 数据库表已建，seed 数据可登录
- [ ] 前端能启动，Axios 封装生效
- [ ] 注册/登录接口跑通（前端 → 后端 → 数据库全链路）
- [ ] 接口契约文档已落地

## 9. 答辩贡献展示建议

- **前端**：演示用户端 + 管理端页面，讲路由权限、表单校验、接口封装。
- **后端 A**：讲认证、产品，以及风控与信用评估预留接口的设计。
- **后端 B**：讲申请审批流、放款、还款计划生成、逾期罚息计算（重点展示利息公式的正确性）。
- **全栈**：讲数据库 ER 设计与建表、联调流程、测试用例、部署与文档，说明自己贯穿全流程的「胶水」价值。
