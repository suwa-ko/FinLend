# 02 · 功能需求分析

## 1. 系统概述

借贷软件平台面向两类用户，提供从「注册认证 → 借款申请 → 审批放款 → 按期还款」的完整借贷业务闭环，并配套后台管理功能。

## 2. 用户角色与权限

| 角色 | 说明 | 主要权限 |
| --- | --- | --- |
| 借款人（普通用户） | 已实名认证的借款用户 | 浏览贷款产品、申请借款、查看借款/还款、还款、账户管理 |
| 管理员 | 平台运营人员 | 用户管理、产品管理、审批、放款、逾期催收、统计报表 |

> 权限控制：前端路由守卫 + 后端接口基于 JWT 角色校验双重控制。管理端接口需 `ROLE_ADMIN`。

## 3. 功能模块划分

```
借贷软件平台
├── 1. 用户模块
├── 2. 贷款产品模块
├── 3. 借款申请模块
├── 4. 信用评估模块（本期预留接口）
├── 5. 放款与账户模块
├── 6. 还款模块
├── 7. 后台管理模块
└── 8. 消息通知模块
```

## 4. 各模块详细功能

### 4.1 用户模块

| 功能 | 说明 | 要点 |
| --- | --- | --- |
| 注册 | 手机号 + 验证码 / 账号密码注册 | 手机号唯一；验证码通过 Redis 5 分钟过期 |
| 登录 | 手机号/账号 + 密码登录，返回 JWT | 密码 BCrypt 校验；令牌过期时间可配（默认 2h） |
| 退出登录 | 使令牌失效 | 令牌加入 Redis 黑名单 |
| 实名认证 | 提交姓名、身份证号、人脸/证件照（可简化为表单） | 身份证 18 位校验；认证通过才可借款 |
| 个人信息管理 | 查看/修改昵称、邮箱、职业、收入、居住地址 | 职业/收入字段预留（供下学期信用评估使用） |
| 银行卡绑定 | 绑定放款/还款银行卡 | 卡号校验；用于放款与自动扣款 |
| 账户信息 | 查看账户余额、可用额度 | 信用分字段预留，本期不展示 |

### 4.2 贷款产品模块

| 功能 | 说明 | 要点 |
| --- | --- | --- |
| 产品列表 | 展示可借产品（名称、额度区间、利率、期限、还款方式） | 登录用户可浏览 |
| 产品详情 | 查看产品完整规则、费用说明、还款示例 | 用示例演示利息计算 |
| 产品管理（管理员） | 新增/编辑/上架/下架产品 | 下架产品不再接受新申请 |

**产品关键字段**：产品编号、名称、最小/最大额度、年化利率区间、借款期限范围、还款方式（等额本息/等额本金/先息后本）、逾期罚息日利率、状态。

### 4.3 借款申请模块（核心）

| 功能 | 说明 | 要点 |
| --- | --- | --- |
| 额度试算 | 输入金额、期限，实时展示应还总额、利息、每期还款 | 前端展示 + 后端重算 |
| 提交申请 | 选择产品，填写借款金额、期限、用途、还款方式 | 金额须在产品区间内且 ≤ 可用额度 |

| 撤销申请 | 待审核状态可撤销 | — |

### 4.5 放款与账户模块

## 5. 核心业务流程图

### 5.1 借款主流程

```
注册 → 实名认证 → (可选)绑定银行卡 → 浏览产品 → 额度试算
  → 提交借款申请 → 管理员审批（信用评估本期预留，默认通过）
      ├─ 拒绝 → 通知用户（结束）
      └─ 通过 → 签约确认 → 放款 → 生成还款计划
                  → 按期还款 / 提前还款 / 逾期处理 → 结清（结束）
```

### 5.2 审批状态机

```
待审核(PENDING) ──通过──► 待签约(APPROVED) ──用户确认──► 待放款
      │                                                  │
      ├──拒绝──► 已拒绝(REJECTED)                        ▼
      └──撤销──► 已撤销(CANCELLED)              已放款(LENT)
                                                  │
                                    ┌─────────────┼─────────────┐
                                    ▼             ▼             ▼
                                还款中        已结清        已逾期(可转还款中)
```

## 6. 关键业务规则

### 6.1 利息计算（三种还款方式）

设：本金 `P`、月利率 `r`（= 年利率/12）、期数 `n`。

**① 等额本息**（每期还款额固定）

```
每期还款额 A = P × r × (1+r)^n / [(1+r)^n − 1]
每期利息 = 剩余本金 × r
每期本金 = A − 每期利息
```

**② 等额本金**（每期本金固定，利息递减）

```
每期本金 = P / n
每期利息 = 剩余本金 × r
每期还款额 = 每期本金 + 每期利息
```

**③ 先息后本**（每月只还利息，最后一期还本金 + 当期利息）

```
每期利息 = P × r（最后一期前）
最后一期 = P + P × r
```

### 6.2 逾期罚息

```
罚息 = 逾期应还本金 × 罚息日利率 × 逾期天数
罚息日利率 = 产品配置（如年利率 × 1.5 / 360）
```

### 6.3 提前还款

- 等额本息/等额本金：提前还款需偿还「剩余本金 + 当期截止日的利息 +（可选）违约金」。
- 违约金可在产品中配置（如剩余本金的 1%，或前 N 期不允许提前还款）。

### 6.4 授信额度

```
可用额度 = 授信额度 − 未结清借款本金
授信额度（本期）= 固定默认额度（如 50000，管理员可在后台为用户设置）
授信额度（下学期预留）= min(产品上限, 月收入 × 收入系数 × 信用分系数)
```

### 6.5 信用评分规则（下学期预留）

> 本期不实现信用评分，用户统一使用默认信用分（60、等级 C）。下表为下学期评分规则设计参考。

| 维度 | 分值区间 |
| --- | --- |
| 月收入 | 0–30 分（收入越高分越高） |
| 历史还款记录 | 0–30 分（每正常结清一次加分） |
| 逾期次数 | 0–30 分（每逾期一次扣分） |
| 账户完整度 | 0–10 分（实名/绑卡/资料完整） |

- 信用分区间 → 等级：`≥90 A`、`≥75 B`、`≥60 C`、`<60 D`（下学期实现）。
- D 级自动拒绝（下学期实现）；黑名单拦截本期实现。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 常规接口响应 ≤ 500ms；支持课程演示的并发即可（无需高并发优化） |
| 安全 | 密码加密存储、JWT 鉴权、越权校验、金额 Decimal、敏感信息脱敏 |
| 可用性 | 关键操作给出友好错误提示；表单前端+后端双重校验 |
| 可维护性 | 分层清晰、统一返回结构、统一异常处理、接口文档（FastAPI 自带 Swagger） |
| 兼容性 | 前端支持主流现代浏览器（Chrome/Edge） |

## 8. 数据边界与异常场景

1. 用户重复提交同一借款申请（同一时间仅允许一笔待审核申请）。
2. 放款时账户并发扣减导致超额（数据库乐观锁/事务保证）。
3. 还款金额超过应还金额（多还部分转为账户余额或原路退回）。
4. 审批通过但用户不签约（超时自动失效）。
5. 还款日遇节假日（按自然日计算，不做顺延，简化处理）。
6. 用户被冻结期间的申请与放款需拦截。
