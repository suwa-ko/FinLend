## 2. 架构与开发模式

| 术语         | 英文/全称                         | 通俗解释                                                                             | 在本项目中                                   |
| ------------ | --------------------------------- | ------------------------------------------------------------------------------------ | -------------------------------------------- |
| 前端         | Front-end                         | 用户在浏览器或手机 App 里看到并操作的界面                                            | Web 使用 Vue 3；安卓端使用 uni-app           |
| 后端         | Back-end                          | 跑在服务器上、负责数据与业务规则的那部分                                             | FastAPI 写的部分                             |
| 前后端分离   | Front-end / Back-end Separation   | 把「界面」和「业务逻辑」拆成两个独立程序，各自开发、通过网络通信                     | 本项目的**总体架构**                         |
| 接口 / API   | Application Programming Interface | 两个程序约定好的「对话方式」：一方按格式发请求，另一方按格式回数据                   | 前端通过 API 向后端要数据                    |
| RESTful      | Representational State Transfer   | 一种主流的 API 设计风格：把数据看作「资源」，用 GET/POST/PUT/DELETE 等标准动作操作它 | 本项目所有后端接口的设计风格                 |
| HTTP / HTTPS | HyperText Transfer Protocol       | 浏览器与服务器之间传数据的「普通话」；HTTPS 是它的加密版                             | 前后端通过 HTTP 传 JSON                      |
| JSON         | JavaScript Object Notation        | 一种人和机器都能看懂的文本数据格式，形如 `{"name":"张三","age":20}`                  | 前后端之间传递的数据格式                     |
| 单页应用     | SPA, Single Page Application      | 整个网站只有一个网页，切页时不重新加载，由 JS 动态替换内容                           | Web 用户端和管理端采用 SPA                   |
| 单体架构     | Monolith                          | 所有功能放在一个程序里一起部署                                                       | 本项目后端采用单体，不用微服务               |
| 分层架构     | Layered Architecture              | 把代码按职责分层，上层调用下层，各层只管自己的事                                     | 路由层 → 业务层 → 数据访问层                 |
| 接口契约     | API Contract                      | 前后端事先约好「请求长什么样、响应长什么样」，之后各自照此开发                       | 约定后再并行开发，避免返工                   |
| 脚手架       | Scaffold / Boilerplate            | 项目刚创建时的基础骨架代码，含基本配置                                               | 第 1 天要搭的「最小可运行骨架」              |
| 中间件       | Middleware                        | 在请求被真正处理前后插入的一段公共逻辑（如鉴权、日志）                               | 统一鉴权、统一异常处理                       |
| 跨域 / CORS  | Cross-Origin Resource Sharing     | 浏览器限制脚本读取跨源响应，CORS 用于声明允许的源；不是身份认证                      | Web 配置明确允许源，所有端仍需鉴权           |
| CRUD         | Create / Read / Update / Delete   | 增、查、改、删四种最基础的数据操作                                                   | 产品管理等模块本质就是 CRUD                  |
| 微服务       | Microservices                     | 把系统拆成很多个小服务，各自独立部署                                                 | ⚠️ 不采用：业务规模小，单体足够              |
| 消息队列     | Message Queue                     | 在生产者与消费者之间异步传递任务/事件，可用于解耦和削峰                              | 本期不引入独立消息中间件，消息与业务同库提交 |
| 分布式事务   | Distributed Transaction           | 跨多个数据库/服务保证数据一致                                                        | ⚠️ 不采用：单库事务已足够                    |
| 规则引擎     | Rule Engine                       | 将条件和决策规则集中管理的组件                                                       | 本期不引入；固定黑名单检查在业务代码中执行   |

## 5. 数据库与数据

| 术语             | 英文/全称                   | 通俗解释                                                | 在本项目中                                      |
| ---------------- | --------------------------- | ------------------------------------------------------- | ----------------------------------------------- |
| 关系型数据库     | RDBMS                       | 用「表格」存数据的数据库，表与表之间可建立关联          | MySQL                                           |
| MySQL            | —                           | 最流行的开源关系型数据库                                | 存放核心业务数据                                |
| Redis            | —                           | 常用于缓存和临时状态的数据存储                          | 验证码、限流；会话与幂等结果持久化到 MySQL      |
| 非关系型数据库   | NoSQL                       | 采用文档、键值等模型的数据库类别，事务能力因产品而异    | 不增加 MongoDB 等业务主库；Redis 仍用于临时数据 |
| 表 / 字段 / 记录 | Table / Column / Row        | 表 = 一张二维表；字段 = 一列；记录 = 一行               | 见《03-数据库设计》                             |
| 主键             | Primary Key, PK             | 能唯一标识一行数据的字段                                | 每张表的 `id`                                   |
| 外键             | Foreign Key, FK             | 指向另一张表主键的字段，用来建立关联                    | 如 `user_id`                                    |
| 索引             | Index                       | 给字段建「目录」，让查询更快                            | 见《03》§5                                      |
| ER 图            | Entity-Relationship Diagram | 用图表示「有哪些实体、彼此是什么关系」                  | 见《03》§2                                      |
| 事务             | Transaction                 | 一组数据库变更原子提交或回滚                            | 放款入账、计划、流水和幂等结果一起提交          |
| 回滚             | Rollback                    | 事务失败时，把已做的改动全部撤销                        | 出错时恢复原状                                  |
| 悲观锁 / 行级锁  | Pessimistic Lock            | 先锁住那行数据再改，别人只能等着                        | `SELECT ... FOR UPDATE`                         |
| 乐观锁           | Optimistic Lock             | 更新时检查版本号，失败则重读并重新判断业务条件          | 不能盲目重试已改变含义的请求                    |
| 并发             | Concurrency                 | 多个人同时操作同一份数据                                | 需要防止超额扣款                                |
| 精度 / DECIMAL   | Precision                   | 十进制定点/十进制运算减少二进制表示误差，但仍需明确舍入 | 金额两位、ROUND_HALF_UP、最后一期平账           |
| 浮点数           | float                       | 计算机表示小数的方式，存在微小误差                      | ⚠️ 严禁用于金额运算                             |
| 分页             | Pagination                  | 数据太多时一页只显示一部分                              | `limit` / `offset`                              |
| 缓存             | Cache                       | 把常用数据放内存里，减少查询数据库                      | Redis                                           |
| 状态机           | State Machine               | 用「状态 + 允许的转移」来描述业务流程                   | 借款申请状态，见《02》§5.2                      |
| 逻辑删除         | Soft Delete                 | 标记不可见而非物理删除                                  | 账务历史不删除；产品下架与账号冻结用状态表达    |

## 6. 安全与鉴权

| 术语       | 英文/全称             | 通俗解释                                             | 在本项目中                                          |
| ---------- | --------------------- | ---------------------------------------------------- | --------------------------------------------------- |
| 认证       | Authentication        | 确认「你是谁」（登录）                               | 用户登录                                            |
| 授权       | Authorization         | 确认「你能干什么」（权限）                           | 普通用户 vs 管理员                                  |
| JWT        | JSON Web Token        | 一种登录凭证（令牌），服务器签发后前端每次请求带上它 | 本项目的登录鉴权方式                                |
| 令牌       | Token                 | 证明「我已登录」的一串字符串                         | 放在请求头 `Authorization` 中                       |
| 令牌黑名单 | Token Blacklist       | 记录应拒绝的令牌或会话                               | 本期以会话吊销状态为准，Redis 只可作辅助缓存        |
| 哈希       | Hash                  | 将输入映射为摘要；通用哈希不适合直接存口令           | 密码用 BCrypt；高熵刷新令牌用 SHA-256 摘要          |
| BCrypt     | —                     | 一种专为密码设计的哈希算法（自带「加盐」）           | 配合 passlib 使用                                   |
| 加盐       | Salt                  | 给密码掺入随机字符再哈希，防止被对照表破解           | BCrypt 自动处理                                     |
| 验证码     | OTP / CAPTCHA         | OTP 为一次性代码；CAPTCHA 为人机验证，两者不同       | 本期注册演示代码 5 分钟过期、单次消费，不接真实短信 |
| 越权校验   | —                     | 防止用户访问本不属于他的数据                         | 后端每个接口都校验                                  |
| 脱敏       | Masking               | 敏感信息显示时打码，如 `138****8888`                 | 身份证、手机号、银行卡号                            |
| 实名认证   | Identity Verification | 对身份资料进行验证的流程；KYC 范围更广               | 本期仅虚构资料格式检查和测试图片，标明模拟          |
| 环境变量   | Environment Variable  | 存放配置（如数据库密码）而不写死在代码里             | 数据库连接、密钥配置                                |

## 8. 借贷业务术语

| 术语            | 英文/全称            | 通俗解释                                               | 在本项目中                                    |
| --------------- | -------------------- | ------------------------------------------------------ | --------------------------------------------- |
| 本金            | Principal            | 借出去的钱本身                                         | 借款金额                                      |
| 利息            | Interest             | 用钱所付的「租金」                                     | 按利率计算                                    |
| 年利率          | Annual Interest Rate | 按年表示的合同利息率；不等同于含全部费用的综合年化成本 | 百分数存储，如 7.2000 表示 7.2%               |
| 月利率          | Monthly Rate         | 计算月息使用的小数比例                                 | 数据库存储年利率 / 100 / 12                   |
| 等额本息        | Equal Installment    | 每期还款总额相同，前期利息多、本金少                   | 三种还款方式之一                              |
| 等额本金        | Equal Principal      | 每期还的本金相同，利息逐期减少                         | 三种还款方式之一                              |
| 先息后本        | Interest-first       | 平时只还利息，最后一期一次性还本金                     | 三种还款方式之一                              |
| 还款计划        | Repayment Schedule   | 放款时生成的清单：每期该还多少、何时还                 | 见《03》§3.5                                  |
| 逾期            | Overdue              | 到期日次日仍有未清偿款项                               | 计划状态或聚合标志，不是新的申请状态          |
| 罚息            | Penalty Interest     | 逾期未还本金产生的额外费用                             | 按日计提、分日舍入、重跑不重计，不对利息复利  |
| 提前还款        | Early Repayment      | 到期前归还贷款                                         | 本期仅整笔提前结清，未来利息减免有记录        |
| 违约金          | Prepayment Penalty   | 提前还款时按约定收取的费用                             | 产品中可配置                                  |
| 授信额度        | Credit Line          | 允许占用的借款本金上限                                 | 默认 50000.00，管理员可调；区别于账户现金余额 |
| 信用评分 / 等级 | Credit Score / Level | 根据收入、还款记录等算出的信用好坏                     | 本期预留，后续阶段实现                        |
| 风控            | Risk Control         | 控制放贷风险的一整套规则                               | 黑名单拦截本期实现                            |
| 审批            | Approval             | 管理员决定这笔借款批不批                               | 状态机核心环节                                |
| 放款            | Disbursement         | 贷款资金进入借款人账户                                 | 本期模拟余额增加，生成计划与正数流水          |
| 结清            | Settlement           | 本金利息全部还完，借款结束                             | 业务终态                                      |
| 催收            | Collection           | 对逾期用户的提醒与追讨                                 | 逾期管理模块                                  |
| 黑名单          | Blacklist            | 被拉黑的用户，申请会被自动拒绝                         | 见《03》§3.11                                 |
| 账户流水        | Account Flow         | 账户每一笔金额变动的记录                               | 见《03》§3.8                                  |
| 账户余额        | Account Balance      | 借款人可用模拟现金                                     | 放款增加、还款减少；本期不设计冻结金额        |

| 集成测试            | Integration Test          | 测试多个模块接在一起是否正常        | 放款流程                               |
| 验收测试            | UAT, User Acceptance Test | 按需求逐条验证功能是否达标          | M1 ~ M4 检查点                         |
| 测试用例            | Test Case                 | 一条具体的「输入 → 期望输出」       | 覆盖典型金额场景                       |
| 部署                | Deployment                | 把程序放到能长期运行的环境上        | 本地 `uvicorn` 或 Docker               |
| 生产环境 / 开发环境 | Production / Development  | 正式对外服务的环境 / 开发调试的环境 | 本项目以本地演示为主                   |

## 10. 跨端与账务补充术语

| 术语          | 含义                               | 本项目约定                                                |
| ------------- | ---------------------------------- | --------------------------------------------------------- |
| APK           | Android 应用安装包                 | M1 首次真机安装，M4 交付签名包；H5 调试不能替代           |
| HBuilderX     | uni-app 开发及配套打包工具         | 记录实测版本、签名及构建环境                              |
| Access token  | 调用业务 API 的短期凭证            | JWT，默认 2 小时；服务端还检查会话状态                    |
| Refresh token | 换取新 access token 的凭证         | 高熵随机串、服务端存摘要、每次轮换；会话固定 7 天         |
| sid           | 会话标识                           | 用户或管理员各设备登录对应独立会话                        |
| 安全存储      | 借助系统保护机制保存凭证           | App 刷新令牌使用经验证的安全存储；普通 uni storage 不等价 |
| 幂等          | 重复执行相同请求不产生额外业务效果 | 同一主体/操作/键绑定请求内容，成功结果与业务原子保存      |
| 规则快照      | 业务发生时复制并保留当时规则       | 产品修改不能改变已有申请的利率和费用                      |
| 可用额度      | 授信中尚未被本金占用的部分         | 授信减未还本金；与现金余额分别计算                        |
| 还款订单/分摊 | 一次扣款及其对多期计划的分配       | 订单金额等于分项现金合计加违约金                          |
| 利息减免      | 提前结清不再收取的计划利息         | waived_interest 单独保存，不覆盖原计划                    |
| 对账          | 验证不同记录表达的金额一致         | 余额、流水、订单与计划分摊互相核对                        |
| is_mock       | 模拟数据标记                       | 默认评分/风控结果明确标注，不能作为真实评估依据           |

业务规则变化应以 [02-功能需求分析](02-功能需求分析.md) 为准，并同步相关数据设计和术语；术语表不另设一套业务规则。
