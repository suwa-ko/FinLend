## 1. 引言

### 1.1 编写目的

本报告为**借贷软件平台（FinLend）**编写，该产品面向高校「综合设计 1」课程设计项目（版本 v1.0）。

开发该平台的意义在于：以一个**完整的借贷业务闭环**（注册认证 → 借款申请 → 审批放款 → 按期还款）为载体，训练团队在需求分析、系统设计与工程协作方面的能力。产品的核心目标为「**业务流程跑通 + 关键业务规则正确**」，其中利息计算、审批流转、还款与逾期处理是关键业务规则。

本报告详尽说明该软件产品的需求规格，作为后续概要设计、详细设计、编码、测试与验收的依据。**覆盖范围**：本学期（综设1）交付 Web 用户端、Web 管理端和 uni-app 安卓借款人端。信用评分、动态授信额度与多数据融合风控仍属后续扩展，本期仅预留接口，详见《06-扩展与演进规划》。

### 1.2 项目风险

本阶段涉及三类风险承担者：

| 风险承担者 | 本项目对应方        | 本阶段主要风险                                                                                                                                                   |
| ---------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 任务提出者 | 课程组 / 指导教师   | 需求理解偏差导致交付物与课程要求不符；验收标准不够明确                                                                                                           |
| 软件开发者 | 4 人开发团队        | 需求分析不充分导致后期返工；业务规则（利息 / 审批 / 逾期）理解错误；进度延误；技能不足；**本学期新增安卓端交付**，APK 打包 / 签名与 uni-app 平台差异存在受阻风险 |
| 产品使用者 | 模拟借款人 / 管理员 | 功能与真实借贷习惯不符；关键操作路径不顺畅；错误提示不清晰                                                                                                       |

〔待确认〕是否需要补充风险的发生概率、影响程度与应对措施（可引用《00-可行性分析报告》§4.3 与《04-团队分工与开发规范》§6）。

### 1.5 产品范围

## 2. 综合描述

### 2.1 产品的状况

本产品为**新建产品**，属于「**新型的、自主型的产品**」——不是既有产品系列的延伸，也不是成熟产品的升级替代。

**与其它系统的关系**：本产品是最终项目《**多数据融合的贷款系统**》的**前置阶段**。演进关系如下：

| 阶段            | 产品形态                                           |
| --------------- | -------------------------------------------------- |
| 综设1（本产品） | 基础借贷平台：完整业务闭环 + Web 端 + 安卓借款人端 |
| 后续阶段        | 信用评分、授信额度动态计算、规则引擎与多端能力完善 |
| 最终项目        | 扩展为多数据源融合风控的贷款系统                   |

**外部接口**：本期不与真实银行、征信机构、支付通道对接，外部依赖仅为基础软件（操作系统、数据库、缓存），接口定义见 §3。

### 2.2 产品的功能

本产品在业务层面划分为 **8 个功能模块**：

```
FinLend 借贷软件平台（Web 用户端 + Web 管理端 + 安卓借款人 App，共用后端与业务数据）
├── 1. 用户与认证    注册、登录/续期/退出、模拟实名、图片上传、个人资料与模拟银行卡
├── 2. 产品          产品浏览、试算参数、上下架管理
├── 3. 申请与审批    提交、撤销、审批、签约、签约超时
├── 4. 风控接口      黑名单检查；评分/自动决策仅返回明确标注的模拟值（is_mock）
├── 5. 放款与账户    模拟放款、额度检查、账户余额与流水
├── 6. 还款          计划、按期/逾期还款、提前结清、罚息
├── 7. 后台管理      用户、产品、审批放款与逾期列表（仅 Web）
└── 8. 消息          审批/放款/还款提醒、消息列表与已读状态
```

**客户端交付**：Web 用户端与 Web 管理端由 Vue 3 实现；**安卓借款人 App 由 uni-app 实现并交付签名 APK**，管理员操作仅在 Web 提供。三端复用同一套 API 与业务数据。

借款主流程（顶层数据流程）：

```mermaid
flowchart TD
    A["注册与登录"] --> B["模拟实名与测试图片上传"]
    B --> C["浏览产品与试算"]
    C --> D["校验状态、黑名单、额度后提交申请"]
    D --> E{"管理员审批"}
    E -- "拒绝" --> F["记录原因并通知"]
    E -- "通过" --> G["72 小时内确认签约"]
    G --> H["管理员再次校验并模拟放款"]
    H --> I["账户入账与生成计划"]
    I --> J["按期还款 / 逾期补缴 / 提前结清"]
    J --> K["结清"]
```

> 各模块的详细功能需求见 §5，本节仅作业务层概览，**不重复展开**。

**非作用领域**（明确不做，以免误解）：不从事真实放贷经营、不提供真实资金通道、不接入征信数据、不处理真实个人敏感信息。

| 限制类型          | 具体内容                                                                                                     |

### 2.6 假设和约束（依赖）

**假设因素**（若不成立将影响项目）：

1. 不接入真实支付通道，放款采用**账户记账**方式模拟（放款增加模拟余额，不划转真实资金）；
2. 不接入外部征信，信用分使用**固定默认值**（60，等级 C），接口标注 `is_mock=true`；
3. 全部使用**虚构测试数据**，身份资料仅做格式检查，上传仅限虚构 JPEG/PNG 测试图片；
4. 使用者具备基本借贷概念（本金、利息、期数、逾期等）；
5. 提交申请**不预占授信**，放款时重新锁定用户并检查可用额度；
6. 一次普通还款结清**最早到期的整期债务**，本期不支持任意部分还款；
7. 业务时区统一 **Asia/Shanghai**，计息日不受客户端本地时区影响。

| 约束类型 | 内容                                                       |

## 3. 外部接口需求

> 本章描述**接口本身**的需求，不描述通过接口取得服务的人的需求（后者见 §2.3 附加用户类）。

### 3.1 用户界面

**GUI 标准**：采用基于 Element Plus 组件库的桌面端 Web 界面，统一布局为「顶部导航 + 侧边菜单 + 内容区」。

**屏幕布局限制**：管理端以表格与表单为主，内容区宽度自适应；Web 用户端适配浏览器窗口宽度；安卓端使用 uni-app 移动端布局，覆盖借款人核心流程。

**界面软件组件**：Web 端使用选单、标准按钮、导航链接、数据表格、表单控件、弹窗、全局消息栏、分页控件、图表；**安卓端**使用 uni-ui 组件（列表、表单、弹窗、加载与空状态），布局按移动端单列 + 页面栈组织。**管理端功能不在 App 提供**。

**显示格式规定**：

| 数据类别 | 格式规定                                                                     |
| -------- | ---------------------------------------------------------------------------- |
| 金额     | 固定两位小数，**右对齐**，带千分位（如 `12,345.67`），单位「元」             |
| 利率     | 展示两位小数（如 `7.20%`）；存储与接口用百分数四位小数（`7.2000` 表示 7.2%） |
| 日期     | `YYYY-MM-DD`                                                                 |
| 时间     | ISO 8601 并带时区（如 `2026-09-22T14:30:00+08:00`），业务时区 Asia/Shanghai  |
| 比例     | 百分比，保留两位小数                                                         |

**传输精度约定**：ID、金额与利率在 JSON 中**以字符串传输**，避免 JavaScript 精度丢失；客户端不得自行决定成交利率或应还金额，**接口结果是权威金额**。

**错误信息显示标准**：采用「全局消息提示 + 表单字段级错误」两层呈现；错误信息使用**中文业务表述**，不暴露技术堆栈细节。后端统一返回 `{ code, message, data }`，`code = 0` 表示成功，非 0 为错误码，前端按 code 统一处理。

| 安卓端   | uni-app（Vue 3）+ uni-ui + Pinia | 构建期（HBuilderX）           | 构建安卓借款人 App；`uni.request` 调用同一 API |
| 打包工具 | HBuilderX                        | 构建期                        | 生成签名 APK；CLI 资源构建不等于已生成 APK     |
| 身份凭证 | PyJWT / passlib[bcrypt]          | 库调用                        | access token 签发与校验、密码哈希              |
| 附件存储 | 服务端非公开上传目录             | 文件系统                      | 存放虚构 JPEG/PNG 测试图片（≤ 5 MiB）          |
| 定时任务 | APScheduler                      | 库调用                        | 逾期补算、还款提醒、签约超时（**单调度实例**） |

**说明**：本期**不集成**任何商业中间件、消息服务或第三方开放平台（不收发真实短信、不接真实身份核验）。

### 3.4 通讯接口

| 项目              | 需求                                                                                                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 网络通讯协议      | HTTP/1.1 + JSON；正式部署要求 HTTPS / TLS（局域网 HTTP 仅限隔离的演示配置，不混入交付配置）                                                               |
| 消息格式          | 响应统一为 `{ code, message, data }`；分页 `data` 含 `items`/`total`/`limit`/`offset`（默认 20，最大 100）                                                |
| HTTP 状态与业务码 | 200/201 成功、401 未认证、403 权限不足或冻结、404 不存在、409 状态或幂等 / 报价冲突、422 参数错误、413 文件过大、415 格式不支持、429 限流、503 依赖不可用 |
| 通讯安全与加密    | 密码经 BCrypt 哈希存储；身份证号、手机号、银行卡号脱敏；JWT 签名校验；会话吊销后旧令牌立即不可用                                                          |
| 鉴权方式          | access token 置于请求头 `Authorization: Bearer <token>`；有效期默认 2 小时                                                                                |
| 会话续期机制      | 安卓端使用 refresh token 换取新令牌（**高熵随机串、服务端只存摘要、每次轮换**）；会话固定 7 天                                                            |
| 多端并存          | Web 与 App 会话独立（各自 `sid`），退出只吊销当前会话；账号冻结吊销全部会话                                                                               |
| 幂等              | 提交/审批/签约/放款/还款等写接口携带 `Idempotency-Key`；同键同内容返回原结果，不同内容返回 409                                                            |
| 数据传输速率      | 无特殊要求（常规 Web / 移动应用，无需实时流式传输）                                                                                                       |
| 同步 / 异步机制   | 以**同步请求—响应**为主；逾期补算、还款提醒与签约超时由服务端定时任务**异步**触发（单调度实例）                                                           |
| 消息获取机制      | App 前台**每 30 秒轮询**未读数，进入消息页刷新，退到后台暂停轮询；本期不要求后台实时推送                                                                  |
| 后续预留          | 厂商消息推送与小程序适配                                                                                                                                  |
