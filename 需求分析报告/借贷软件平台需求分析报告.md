# 1. 引言

## 1.1 编写目的

定义FinLend v1.0的需求范围，明确借款人和管理员可执行的操作、操作条件、金额计算、异常结果与验收标准，为概要设计、详细设计、编码和测试提供依据。

产品以注册认证、借款申请、审批签约、模拟放款、按期或逾期还款及结清为主线。成功标准是流程可演示、金额可核对、权限与异常行为可验证；信用评分、动态授信和多源风控不作为本期真实决策能力交付。

本报告保留计算公式、输入输出与验算示例，因为这些内容决定用户应还多少，且原模板要求明确计算过程。程序类名、接口路径、锁和事务步骤、物理表结构、任务配置、打包命令不作为本报告正文内容。

## 1.5 产品范围

**产品描述**：一个**基础的借贷软件平台**。借款人可通过 Web 用户端或本学期交付的安卓 App 注册、完成模拟实名、浏览贷款产品、试算、提交借款申请并签约，在放款后按期还款或提前结清；管理员在 Web 管理端管理用户、贷款产品、审批流程、放款与逾期催收；系统按固定业务规则计算利息与罚息，并保证重复请求与并发操作后的账务结果一致。

**产品目标（与业务策略的联系）**：本项目不以商业收益衡量成果。它服务于三项课程目标——① 用一条完整业务链展示多角色状态流转；② 用金额计算与重复操作的正确结果展示「关键业务规则正确」；③ 用「Web + 安卓双端共用一套 API」展示跨端一致性与接口契约协作。因此产品的成功判据是**闭环可演示、金额可核对、规则可验证**，而不是用户量、放款规模或风险指标。

**利益**：团队成员获得从需求分析到 APK 交付的完整工程经历；产出可复用的接口契约、数据库迁移、测试基准与部署手册。

**范围边界**

| 类别 | 内容 |
| --- | --- |
| 必须交付 | 注册登录与会话续期、模拟实名与测试图片上传、产品浏览与管理、额度试算、申请/撤销/签约、审批、模拟放款、还款计划、按期与逾期还款、提前结清、逾期罚息、账户与流水、站内消息、**Web 基础后台管理**、**安卓 APK** |
| 配套交付 | 可重复的数据初始化与恢复材料、接口契约、测试记录与算例、安装部署指南与用户手册、演示与答辩材料 |
| 可选增强 | 统计图表与导出、催收备注、模拟充值页面（提供有来源的基础演示资金） |
| 后续扩展 | 信用评分与动态额度、多数据融合风控、小程序、厂商推送、真实身份核验、真实资金通道（本期只预留接口/表设计） |
| 本期排除 | 真实放贷与真实资金划转、真实征信与身份核验、真实个人敏感资料采集、任意部分还款、银行卡自动扣款 |

**非作用领域**（避免误解）：本产品**不是**真实的借贷服务，不满足金融业务的合规要求，不产生任何真实债权债务；本产品的信用分 60 与等级 C 是**模拟默认值**，不代表任何真实信用评估结果；本产品的「余额」是演示用模拟现金，不是可提现资金。

# 2. 综合描述

## 2.1 产品的状况

FinLend是自主开发的课程演示产品，不是已有商业系统的替换或升级版本。Web与安卓提供同一借款人业务，管理员通过Web处理产品、用户、申请和放款。系统独立保存演示数据，不依赖外部机构的授信或资金服务。

外部关系包括浏览器、安卓设备、服务端数据存储及测试附件存储。验证码通过演示通道提供，不接短信网关；身份核验、银行卡和账户余额均须明确显示模拟性质。不连接真实支付清算、征信、人脸识别或厂商推送。

## 2.2 产品的功能

本节从**业务层面**概略总结产品功能，详细规格见 §5。括号内为对应用例范围。

**F1 用户与认证**（UC-01~UC-05）★
访客注册；借款人登录、会话续期与退出；模拟实名认证与测试证件图片上传；个人资料维护与模拟银行卡管理（绑定、删除、设置唯一默认卡）；账户信息查询（余额、授信、可用额度）。

**F2 贷款产品与试算**（UC-06）★
借款人浏览上架产品列表与详情（金额与期限范围、年利率、还款方式、罚息与提前结清费率）；使用后端返回的逐期计划与应还总额进行试算。管理员创建、修改与上下架产品。

**F3 借款申请与签约**（UC-07、UC-08、UC-10）★
选择产品、试算、填写金额/期限/用途后提交申请；查询本人申请列表与详情；在「待审核」状态撤销申请；审批通过后在 72 小时内确认签约。

**F4 审批与放款**（UC-09、UC-11）★
管理员的待审批列表与详情查看；通过/拒绝审批（拒绝原因必填）；签约超时自动置为已失效；管理员对「待放款」申请执行模拟放款。

**F5 还款与逾期**（UC-12~UC-15）★
查看还款计划；对**最早到期的整期债务**发起按期或逾期还款；整笔提前结清（先报价后确认）；按日计提逾期罚息并支持漏跑补算；查看还款订单与分摊明细。

**F6 账户与流水**（UC-12）★
查看模拟现金余额、账户流水（含演示初始化流水、放款入账、还款出账）；每笔业务有可追踪编号。

**F7 后台管理**（UC-17~UC-19 必需；UC-20 可选）
用户查询/冻结/解冻；产品管理；黑名单管理；逾期借款列表；统计报表（放款总额、待还总额、逾期率、用户数）。

**F8 站内消息**（UC-16）★
审批结果、放款成功、到期前 3 天提醒、逾期提醒的站内消息；未读数与已读状态；App 前台 30 秒轮询未读数。

**F9 风控与信用接口**（UC-07、UC-08、UC-12、UC-18、UC-22）★
黑名单检查为**本期唯一真实执行的风控规则**；评分/决策/数据源/信用分接口返回带 `is_mock=true` 的模拟值，仅用于联调，**不能覆盖**实名、冻结、黑名单或额度检查，也不等于管理员审批通过。

**F10 安卓端交付**（UC-21）★
复用上述借款人必需功能（含签约与撤销入口）；签名 APK 在指定真机完成一次安装与完整借还流程；管理操作在 Web 演示。

**F11 后续扩展**〔预留〕
动态信用评分、动态授信额度、多源数据融合风控与可解释决策、小程序、厂商推送。本期只保留接口形状与表结构设计，不实现，见 [docs/06](../docs/06-扩展与演进规划.md) §3。

**非作用领域**：本产品提供**借款**方向业务，不含存款/理财/授信外的资金归集业务；不含面向第三方的开放 API 与对外对账；不含真实催收、法律与征信报送流程。

**说明**

- 「用户不一定是软件产品的直接使用者」——课程组/评委与运维者通过**报表、接口文档、部署脚本**获得产品的数据与服务，因此作为附加用户类列出其需求（结果可复现、文档齐全），详见 §6.6 与 §6.2 NFR-SEC-11。
- 借款人**未完成模拟实名不能发起借款申请**；账号被冻结后不能登录、续期、申请或放款，但既有债务与罚息继续存在。
- 管理员权限**每次调用校验**，不能以客户端传入的角色字段获得权限。

## 2.4 运行环境

| 环境 | 需求 |
| --- | --- |
| 服务端 | 团队现有PC，Windows含WSL2或Linux；能运行统一后端、数据库、缓存和任务服务 |
| Web终端 | Chrome或Edge；用户端和管理端均在浏览器操作 |
| 安卓终端 | 至少一台可安装签名APK的Android真机；最低版本和机型在M1冻结 |

建议服务端可用内存不少于4GB、可用磁盘不少于10GB，仍需按实际环境确认。完整运行时版本、安装路径、端口与构建工具配置由详细设计第2章和部署记录管理。

## 2.5 设计和实现上的限制

| 编号 | 标准项 | 要求 |

| UI-13 | 时间显示 | 统一显示北京时间（Asia/Shanghai），格式 `YYYY-MM-DD HH:mm`；到期日仅显示日期 |

### 3.1.2 Web 用户端（借款人）逻辑界面

必须覆盖注册登录、资料与模拟实名、产品浏览试算、申请列表与详情、撤销签约、账户流水、还款计划与结清、消息。申请详情显示规则快照与签约截止；还款界面分别列出本金、利息、罚息和费用。页面布局与路由归入详细设计第6章。

### 3.1.3 Web 管理端（管理员）逻辑界面

提供独立管理登录、用户产品管理、黑名单、审批、放款及逾期列表。审批拒绝要求原因，放款与冻结等操作二次确认。统计图表、导出和催收备注为可选增强。

### 3.1.4 安卓 App（借款人）逻辑界面

覆盖全部借款人必需业务，包含撤销与签约入口。断网、会话过期和操作结果未知均有明确提示；重启后的会话恢复不要求重新输入有效会话的密码。管理操作不在安卓提供。

### 3.1.5 键盘快捷键与功能按钮约定

Web表单可用Enter提交当前合法表单，Esc关闭可取消弹窗；不得绕过危险操作确认。按钮使用明确动作名称；写请求处理中显示加载状态并防止连续点击。具体组件选择不在需求报告规定。

## 3.2 硬件接口

系统通过操作系统提供的文件选择或相册能力获取测试图片，安卓可使用真机现有相机能力选择测试素材，不要求专用摄像头、读卡器、定位或生物识别设备。图片及其类型、大小是需要交换的数据；设备安装和网络访问必须在指定真机验证。

## 3.3 软件接口

### 3.3.1 与外部软件组件的接口

| 外部组件 | 数据或服务 | 外部需求 |
| --- | --- | --- |
| 浏览器与安卓客户端 | 表单、测试图片、查询与操作结果 | 使用同一业务口径，客户端不能直接读写数据库 |
| MySQL数据存储 | 用户、借款、计划、账务与会话等 | 业务持久化、完整性与恢复后对账 |
| Redis临时状态服务 | 演示验证码与访问频率信息 | 不因不可用而跳过所需安全校验 |
| 测试附件存储 | 本人测试证件图片 | 授权读取，不公开他人资料 |

### 3.3.2 后端对客户端提供的服务

需要提供身份认证与会话、个人资料与模拟实名、产品与试算、申请与审批签约、模拟放款、账户流水、还款结清、附件、消息、用户名单管理及模拟风控数据服务。每类服务的输入输出见第5、8章，权限见第2.3节及各用例。具体HTTP路径、方法、请求模型与错误码映射统一在详细设计第5章管理。

## 3.4 通讯接口

客户端与服务端通过HTTP请求响应交换UTF-8数据，正式部署使用HTTPS；隔离局域网演示的明文例外须显式配置。业务响应说明成功、失败及可理解的原因；未知结果不得由客户端推定为已成功或已失败。

金额以十进制字符串表达到分，费率以百分数字符串表达，标识使用字符串以避免大整数精度丢失；日期为YYYY-MM-DD，时刻带北京时间偏移。图片单文件不超过5MiB，仅JPEG/PNG。列表支持分页并保持稳定顺序。

关键写请求须标识同一次逻辑操作。相同主体、操作、键和内容重试返回原结果，同键不同内容拒绝；网络超时后保留原操作标识。访问凭证放请求头，不放URL。未授权、权限不足、状态冲突、金额变化、参数错误、限流和服务不可用须可区分；完整协议字段及HTTP映射见详细设计。

消息采用前台主动查询，间隔30秒；进入后台停止，恢复前台立即刷新。无后台实时推送要求。响应时效见第6.1节，不预先指定未实测的网络带宽或吞吐量。

# 5. 系统功能需求

## 5.1 需求组说明和优先级

> **需求粒度**：本节的 36 个 FR 编号为功能需求组，用于组织业务范围。表中的验收摘要包含多个场景，不作为一条原子需求或一条测试用例。附录 B 将每组拆成具有唯一编号、明确条件和单一验收场景的原子功能需求；每条对应一个 TC 编号。某个场景可以同时检查必要的账务不变量，但成功、非法输入、越权、过期、并发等独立场景分别编号。附录 B 是本报告逐项验收的规格。
> **优先级**：高 / 中 / 低，对应《02》§9 的 P0 / P1 / 后续预留。业务口径以《02》v1.1 为准。

### 5.3.2 计算方法

**① 利率、精度与日期约定**

```
年利率以百分数存储：     7.2000 表示 7.2%
月利率：                 r = annual_rate / 100 / 12
罚息日利率：             penalty_daily_rate 同为百分数，0.0500 表示 0.05%/日
运算：                   十进制精确运算，不允许分位精度损失
舍入：                   四舍五入，每一期金额分别保留到 0.01 元（「逐期舍入」）
业务时区：               Asia/Shanghai
首期到期日：             放款日期 + 1 个自然月
第 k 期到期日：          放款日期 + k 个自然月（每期都从原放款日推算，不从上期到期日递推）
月末规则：               目标月不存在该日时取该月最后一天
                         例：1 月 31 日放款 → 第 1 期 2 月 28 日（闰年 29 日）、第 2 期 3 月 31 日
逾期起算：               到期日当天可还；到期日次日起为逾期；不因节假日顺延
```

**② 等额本息**（每期月供固定）

```
第 1 步  A = round( P × r × (1+r)^n / ((1+r)^n − 1) )
第 2 步  第 k 期利息 I_k = round( 期初剩余本金 × r )
第 3 步  第 k 期本金 C_k = A − I_k                    （k = 1 … n−1）
第 4 步  剩余本金 ← 剩余本金 − C_k，回到第 2 步
平账     第 n 期本金 C_n = P − (C_1 + … + C_{n−1})；第 n 期月供 = C_n + I_n，可因舍入与 A 略有差异
```

**③ 等额本金**

```
第 k 期本金 C_k = round(P / n)                       （k = 1 … n−1）
第 n 期本金 C_n = P − (n−1) × round(P / n)            （平账）
第 k 期利息 I_k = round( 期初剩余本金 × r )
```

**④ 先息后本**

```
第 k 期利息 I_k = round(P × r)                       （k = 1 … n）
第 1 … n−1 期本金为 0；第 n 期本金 = P
```

**⑤ 零利率分支**

```
annual_rate = 0 时：等额本息改用 A = round(P / n)，避免公式除零；三种方式利息均为 0
零利率先息后本的第 1 … n−1 期为零金额计划：生成时直接标记「已还」，不创建零金额扣款，也不产生逾期
```

**⑥ 参数组合合法性**

```
若某一期出现 C_k < 0，或在第 n 期之前剩余本金已 ≤ 0（极小本金 / 过长期数组合）
→ 试算与提交均拒绝该参数组合（422），不生成计划
```

**⑦ 验算基准**（P = 12000.00，annual_rate = 12.0000，r = 0.01，n = 12；文档数值验算基准，不代表软件实现已通过测试）

| 等额本金 | 每期本金 1000.00；首期利息 120.00（月供 1120.00），末期利息 10.00（月供 1010.00），总利息 **780.00** |

**⑧ 逾期罚息与补算**

计费对象为已过到期日且未清偿的该期本金，不对利息和罚息复利。日罚息=四舍五入到分（逾期未还本金×罚息日利率÷100）；总罚息按每个尚未计费的逾期日累加。到期日当天、未来期与已还期不新增罚息。先息后本纯利息期逾期时本金为零，该期罚息为零，但仍显示逾期。

本期不允许任意部分还款，单期未清偿期间本金固定。漏处理k天应补k份日罚息，同日重复处理总额不变。还款当日若已逾期也计一天，成功还清后停止该期计费。例：本金1000.00、日利率0.0500%，每日0.50，连续3天合计1.50。计费进度字段和补算程序见详细设计C10。

**⑨ 提前结清**（仅整笔结清，三种方式均适用）

```
结清金额 S = ① 全部未还本金
           + ② 到期（含当日）计划的未还利息与未还罚息（先按 ⑧ 补算到当日）
           + ③ 当期日息：下一笔未到期计划的
                 起息日剩余本金 × annual_rate / 100 / 365 × 已经过的自然日
                 且不超过该期未付计划利息
                 起息日 = 上期到期日；首期为放款日；当天放款当天结清，日息为 0
           + ④ 违约金 = 未还本金 × prepay_fee_rate / 100（默认费率 0）
减免       未来期利息与当期未计收部分记为 waived_interest，保留原计划利息，不覆盖
费用       违约金独立记入还款订单 prepay_fee，不能伪装成本金或罚息
特例       若已到最后到期日，按全额到期结清处理，不收违约金
流程       返回报价（不扣款）→ 用户提交确认金额 + 幂等键 → 后端重新核对当前金额
           → 金额一致才扣款；不一致返回 409，不能按过期报价扣款
例         P = 12000.00、年利率 12.0000%、2026-01-01 放款、2026-01-11 结清、费率 0
           ① 12000.00  ② 0.00（未有到期期）  ③ 12000 × 12 / 100 / 365 × 10 = 39.45  ④ 0.00
           S = 12039.45；等额本息下 waived_interest = 794.23 − 39.45 = 754.78
```

**⑩ 授信额度与余额**

```
已占用额度 = Σ(已放款未结清计划的 principal − paid_principal)
可用额度   = max(0, credit_line − 已占用额度)
只按未还本金占用，归还本金后立即释放；利息与罚息不占授信
授信 ≠ 余额：放款使余额增加、还款使余额减少；申请/审批/签约不扣现金、不预占额度
放款时重新核对可用额度，多笔待放款申请也不得合计超额
管理员调整授信：新 credit_line 不得低于当前已占用额度
```

**⑪ 应还余额**（单期与汇总）

```
单期应还余额 = principal − paid_principal + interest − paid_interest − waived_interest + penalty − paid_penalty
用户待还总额 = Σ 单期应还余额（status ≠ 已还）
订单金额     = Σ 分摊(本金 + 利息 + 罚息) + prepay_fee        （减免不参与现金扣款）
```

## 6.2 安全措施需求

| 编号 | 风险 | 需求 |
| --- | --- | --- |
| NFR-SEC-01 | 密码泄露或被静默改写 | 不保存或返回明文密码；超长密码明确拒绝，不截断 |
| NFR-SEC-02 | 凭证被盗或伪造 | 校验访问凭证真实性、有效期与会话；续期后旧刷新凭证失效 |
| NFR-SEC-03 | 已退出或冻结仍可访问 | 退出立即终止当前会话；冻结立即终止全部会话；固定7天不因续期延长 |
| NFR-SEC-04 | 访问他人数据或越权管理 | 用户仅访问本人资源，管理员权限不能由客户端自报 |
| NFR-SEC-05 | 附件泄露 | 测试图片只向所属用户或授权管理员提供，不暴露公共路径 |
| NFR-SEC-06 | 重复提交造成重复记账 | 同一业务请求重复执行只产生一份有效结果 |
| NFR-SEC-07 | 并发超额放款或重复扣款 | 同用户并发也不能超额度、超余额或多次执行同一状态动作 |
| NFR-SEC-08 | 依赖异常跳过安全判断 | 无法完成必要校验时拒绝交易；不得降级放行或部分记账 |
| NFR-SEC-09 | 暴力登录或验证码滥用 | 频繁请求可被限制，并给出稍后重试提示；阈值M1确认 |
| NFR-SEC-10 | 客户端篡改金额或精度丢失 | 后端确定最终金额；计算与传输不丢失分位精度 |
| NFR-SEC-11 | 数据丢失 | 可初始化、备份和恢复；恢复后余额、流水与债务对账一致 |
| NFR-SEC-12 | 密钥和测试资料泄露 | 凭据与签名私钥不入库；日志不泄露令牌、密码和完整身份资料 |

实现上述要求的密码算法、持久化、并发与存储机制分别见概要设计第5章及详细设计C01、C02、C07至C12、C19。

## 6.3 安全性需求

身份授权区分访客、借款人和管理员；除注册登录等公开入口外，业务服务验证有效身份。用户修改资源标识不能取得他人借款、账户、消息或附件。管理员登录独立，普通用户凭据不得获取管理权限。

系统保存可核对的历史账务。余额等于全部现金流水合计；计划已付与减免等于对应还款分项合计；每次扣款等于分项现金加独立费用；结清后本金、利息与罚息均无剩余。账务历史不能因用户冻结、产品下架或名单移出而被删除。

| 资料 | 保护与展示要求 |
| --- | --- |
| 模拟证件号 | 只用虚构号码，展示前3后4，其余遮蔽 |
| 模拟手机号 | 展示如138****8888，日志脱敏 |
| 模拟卡号 | 只显示后4位，不参与真实划转 |
| 密码与令牌 | 不进入URL或日志，不对外返回密码；终端退出清理凭证 |
| 测试图片 | 明确禁止上传真实证件；未授权主体不可读取 |

冻结期间会话失效，既有债务与罚息继续；需解冻后由用户偿还。黑名单仅限制新申请与放款，不禁止查询和清偿既有债务。预置演示账号是否首次改密由Q-22确认，模板中的示例不自动成为需求。

## 8.1 记号与通用类型

组合项以“+”连接，可选项用圆括号，重复项用“{ }”表示，枚举逐项列出。金额为十进制数，单位元，精度0.01；一般金额非负，上限9999999999999999.99，流水可为负。费率单位为百分数，精度0.0001，范围0至9999.9999，实际产品可更窄。金额和费率传输为字符串；超范围或超精度拒绝，不静默截断。

标识为最长19位正整数字符串；日期为YYYY-MM-DD，时刻精确到秒、带+08:00；布尔取真或假。下表中“字符”为业务长度上限，不等于数据库字节数。保密字段只用于输入，不出现在一般查询结果。

# 附录 B 原子功能需求与验收场景

本附录将 §5.1 的 36 个需求组细化为 **193 条原子功能需求**，各自有唯一需求编号和一个验收测试编号。每行定义一个独立场景的条件、触发与预期结果；实现后在测试记录中填写环境、执行步骤、实际结果和证据，本文不填写虚构的通过结果。

测试数据均为虚构。涉及到期、签约截止与令牌期限的场景在隔离测试环境使用受控业务时钟或已知历史数据，不需等待真实月份；业务时间不得由生产接口的客户端任意改写。参数规则的其他边界值可用于补充回归，不能用一个摘要编号掩盖尚未验证的独立行为。

每条原子需求显式列出优先级。需求组的来源、页面、主要数据与里程碑按附录 A 关联；具体执行用例见下表。全部 P0 原子需求均须通过才能判定本期必需功能完成；P1 报表在选择实施后才验收。调用者鉴权、数据格式、幂等和回滚等共同约束同时遵循 §3.4 与 §6，不能因某行仅验证一个场景而省略其他检查。
